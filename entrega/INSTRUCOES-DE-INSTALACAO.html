Novo site Lava Thru — instruções de instalação

Pacote preparado pela Raydix · site institucional estático (HTML + CSS + JS puros, sem build e sem dependências de servidor)

1. O que é este pacote

Este ZIP contém o novo site institucional da Lava Thru, pronto para publicação. Ele substitui apenas as páginas públicas de marketing (home, termos, privacidade). Não contém — e não interfere em — nenhuma lógica de backend.

Arquivo/pastaO que é
index.htmlHome completa (hero interativo, planos, limpeza interna, sobre, contato)
termos.html · privacidade.htmlPáginas legais
assets/css · assets/js · assets/imgEstilos, interações e imagens otimizadas (tudo local, sem CDN além do Google Fonts)

Preview de referência do resultado esperado: https://acceleratolava-maker.github.io/lavathru-site/

2. O que NÃO pode parar (leia antes de tudo)

O sistema atual (área do cliente) continua sendo necessário. O aplicativo Angular que hoje atende /login, cadastro, compra de planos, assinaturas e o painel administrativo não faz parte deste pacote e deve continuar funcionando, junto com a API (/api/…).

O site novo já aponta os botões "Área do cliente" / "Comprar online" / "Assinar agora" para https://www.lavathru.com.br/login. Ou seja: se /login e /api continuarem respondendo como hoje, nenhum link precisa ser alterado.

3. Instalação — opção recomendada (site novo na raiz, app preservado)

  1. Backup: faça uma cópia completa da pasta pública atual do site antes de qualquer coisa.
  2. Envie o conteúdo do ZIP para a raiz pública do domínio (ex.: public_html/ ou equivalente), substituindo o index.html atual e adicionando a pasta assets/ e as duas páginas legais. Não apague os bundles do app Angular (main.*.js, runtime.*.js, styles.*.css etc.) nem qualquer pasta da API.
  3. Ajuste o servidor para que as rotas do aplicativo continuem caindo no app Angular, e não no site novo. O ponto-chave: o fallback de rotas desconhecidas deve continuar indo para o shell do app (como é hoje), exceto a raiz /, que passa a ser o site novo.

Exemplo nginx

# raiz e páginas de marketing -> site novo
location = /              { try_files /index.html =404; }
location = /termos.html      { try_files /termos.html =404; }
location = /privacidade.html { try_files /privacidade.html =404; }
location /assets/            { try_files $uri =404; }

# API continua como está
location /api/ { proxy_pass http://SEU_BACKEND; }

# demais rotas (login, cadastro, minha-conta, admin...) -> app Angular
location / { try_files $uri /index-app.html; }
# obs.: renomeie o index.html ATUAL do Angular para index-app.html
# e mantenha os bundles dele na raiz (ou mova app+bundles para /app/ e
# ajuste o fallback para /app/index.html)

Exemplo Apache (.htaccess)

RewriteEngine On
# API intocada
RewriteRule ^api/ - [L]
# arquivos reais (site novo e bundles do app) são servidos direto
RewriteCond %{REQUEST_FILENAME} -f [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^ - [L]
# rotas do app Angular -> shell do app (renomeado)
RewriteRule ^ index-app.html [L]

Se preferir, uma alternativa igualmente válida: mover o app Angular para um subdomínio (ex.: conta.lavathru.com.br) e manter na raiz só o site novo — nesse caso, criar um redirecionamento 301 de /login para o subdomínio (assim os botões do site novo continuam funcionando sem alteração).

4. Teste pós-instalação (2 minutos)

  • ☐ lavathru.com.br abre o site novo (animação de espuma na primeira visita)
  • ☐ /termos.html e /privacidade.html abrem
  • ☐ Botão "Área do cliente" abre o login do sistema atual normalmente
  • ☐ Login, compra de plano e painel admin funcionando como antes
  • ☐ Botões de WhatsApp abrem a conversa · mapa do Google carrega na seção Contato
  • ☐ Teste no celular (o site é 100% responsivo)

Dica de cache: os arquivos CSS/JS são versionados por query string (?v=8). Ao publicar, não é preciso limpar cache de visitantes — a versão nova carrega sozinha. Em atualizações futuras dos assets, basta subir os arquivos novos com a versão incrementada no HTML.

5. Observações técnicas

  • Único recurso externo: Google Fonts (Fredoka + Hanken Grotesk). Todo o resto é local.
  • SEO já incluso: meta tags, Open Graph (assets/img/og-image.jpg) e dados estruturados JSON-LD (endereço, horários, telefone).
  • Favicon e ícones PWA na pasta assets/img/ (referenciados nos HTML).
  • Acessibilidade: animações respeitam prefers-reduced-motion; a intro de espuma roda 1x por visita e pode ser pulada com clique.
  • Nada de banco de dados, PHP ou build — qualquer servidor de arquivos estáticos serve.
